# Stage 9A candidate selection — cycle 3

Status: pre-result selection record. No comparative candidate backtest was run or
inspected for this decision. Scores allocate research effort; they do not estimate
alpha or authorise a strategy. Neither Cycle 1's `not_evaluable` result nor Cycle
2's `not_material_or_not_consistent` result was relaxed, revisited, or used to
select a candidate below — both remain closed under their own locked rules.

Sourced from the [pending candidate
checklist](../brainstorm/2026-08-19-pending-candidate-checklist.md)'s Tier 0/1
(cheap, single-asset, zero new infrastructure) — the deliberate next step after
Cycle 2, rather than reaching for Tier 2's infrastructure-gated candidates or
Tier 4's paid data. Both candidates below were operationalised and scored before
either was implemented or run.

## Decision

Prioritise **Candidate A — RSI(14) oversold-crossing short-horizon reversal**.
It scores the highest of any candidate in this project's history (`15/16`) and,
if it holds, would be this project's first candidate with a plausible
*negative* correlation to every trend-family idea tested so far (CTA v1, SMA
Cross v1, CTA v2, cross-sectional rotation) — a genuine diversification
property none of the others can claim, not merely a fourth variation on trend.

**Candidate B — S/R Bounce formalization** is not prioritised. Its mechanism —
buy a dip to a rolling N-day low, exit at a rolling N-day high or an ATR stop —
is close enough in shape to Cycle 1's already-closed consolidation
support-recovery detector (test a boundary, recover, go long) that it scores
`0` on distinct information: this would substantially re-ask a question Cycle 1
already spent a full protocol answering, with a cruder, unconfirmed detector
construction (no multi-touch requirement, no zone-width constraint). It remains
eligible for a future cycle only behind a materially different construction
that earns a real distinct-information score, per the same rule that already
governs any future consolidation-matcher attempt.

## Candidate A — RSI(14) oversold-crossing short-horizon reversal

| Field | Pre-result definition |
|---|---|
| Claim | A completed session where RSI(14) newly crosses from `≥30` to `<30` (a fresh transition into oversold, not merely remaining there) is followed by a positive mean forward `K`-session return, and this is not explained by a magnitude-matched raw price-decline trigger alone. |
| Scope | The 12 locked ETFs, adjusted daily OHLCV, full available history; forward horizon `K` locked as one primary value, not a grid. |
| Mechanism | Short-horizon overreaction / liquidity-provision compensation: sharp, rapid declines can overshoot fundamental value under forced selling or panic, and contrarian capital providing liquidity back into that overshoot is compensated by a subsequent partial reversal — a well-studied short-term reversal mechanism (Jegadeesh 1990; Lehmann 1990), distinct from every trend-family mechanism tested so far. |
| Market-belief proxy | RSI(14) itself — Wilder-smoothed ratio of average gains to average losses over the trailing window, representing how one-sided recent price action has been. |
| Reality proxy | Realized forward `K`-session log return following the event. |
| Information set | Adjusted daily OHLCV through the completed close at the event date only; RSI computed causally, no future bar. |
| Estimand | Mean forward `K`-session log return conditional on the event, tested against a block-resampled, event-recomputed null — the same family of method Candidate A of Cycle 2 (SMA Cross v1) already proved out, deliberately avoiding Cycle 1's caliper-matching failure mode by not matching against a separate control set at all. |
| Alternatives | (1) Generic magnitude-based reversal — any sufficiently large decline could bounce regardless of RSI's specific construction; controlled via a frequency-matched raw-decline placebo, mirroring SMA Cross v1's placebo design. (2) Volatility-regime effect — oversold conditions co-occur with elevated volatility, so a larger forward return could be pure risk compensation; the placebo, which also occurs in high-vol regimes, partially addresses this. (3) Market beta/regime — could be "buying the dip in a rising market"; addressed by the bootstrap's null construction. (4) Non-independent overlapping events — requires a cooldown after each event, mirroring Cycle 1's and Candidate A/Cycle 2's precedent. |
| Falsifier | Observed mean forward return is not distinguishable from the block-resampled null at the locked level, or the frequency-matched raw-decline placebo achieves an equal or larger forward-return bounce, showing RSI's specific construction adds nothing beyond a generic "big decline → bounce." |
| Data feasibility | Fully available today — identical 12-ETF adjusted daily OHLCV already used by every prior candidate; no new data source. |
| Expression candidates | (a) No-trade event study (required first bounded experiment): mean/median forward return versus the placebo and versus the bootstrap null. (b) If (a) clears its gate: a long-only single-asset entry-on-event, exit-on-recovery-or-timeout rule, benchmarked separately under its own locked cost/execution protocol. |
| Path and risk | The classic mean-reversion failure mode — repeated shallow oversold excursions inside a genuine downtrend ("falling knife") rather than a true bounce; gap risk between the event close and next-open execution in any later tradeable expression; event clustering around single macro shocks (2008, 2020) could dominate the sample, requiring the same concentration-style check used elsewhere. |

the mechanical data-readiness auto-disqualifier) but it is the load-bearing
reason for the decision above.

## Benchmark suitability

Candidate A's primary comparator at this stage is its own block-resampled null
and the frequency-matched placebo, not Passive ETF-12 v1 — it is a per-event
return claim, not a portfolio-vs-passive claim. If the no-trade study clears
its gate and an executable expression is proposed, Passive ETF-12 v1 becomes
the relevant comparator for that expression, subject to the ADR 0005
suitability audit like every other candidate.

## Next locked deliverable

Write one locked protocol for Candidate A before computing any forward-return
value. It must freeze, at minimum: the forward horizon `K`; the event
cooldown/deduplication rule; the frequency-matched placebo's decline-magnitude
construction; the block-bootstrap procedure's block length, resample count,
and null-construction details; the materiality threshold for the forward
return; and deterministic specification/data fingerprints, per the existing
convention. No entry rule, stop, portfolio backtest, or parameter tuning is
authorised by this selection record.
