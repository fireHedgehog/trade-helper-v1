# Next-priority evaluation

Status: required before new Stage 9A/9B work when >1 candidate is live
(scored, blocked, or brainstormed). Distinct from the 9A scorecard: that
scores one candidate; this ranks across several.

## When

A prior line closes, or a new brainstorm adds a candidate alongside
existing blocked/parked ones. Not required with a single obvious next
step and no live alternative.

## Process

1. Inventory every live candidate: status, blocker, prior score if any.
2. Score/re-score each on [model-acceptance-standard](model-acceptance-standard.md)'s
   8 dimensions; reuse existing evidence before generating new evidence.
3. Adversarially re-check: re-read the prior results/audits a score
   depends on before finalizing — don't let a stale framing (e.g.
   "underpowered" misread as "false") silently bias the ranking.
4. Record inventory, scores, chosen candidate, rejected-and-why in a dated
   `research-candidates/` file or update to an existing one.
5. Output one recommended next candidate. Never start new locked work
   while >1 live candidate exists without this step.
